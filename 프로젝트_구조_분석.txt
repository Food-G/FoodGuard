┌─────────────────────────────────────────────────────────┐
│  STEP 1. FRONTEND - 사용자 입력                          │
└─────────────────────────────────────────────────────────┘

[사용자] 예측 실행 버튼 클릭
    ↓
Predictions.tsx
    └── handleTrigger()
        ├── storeId 확인
        ├── setTriggering(true)
        └── predictionService.trigger(storeId)
                ↓
            services/predictionService.ts
                └── api.post('/predictions/{storeId}/trigger')
                            ↓  HTTP POST 요청


┌─────────────────────────────────────────────────────────┐
│  STEP 2. BACKEND - 요청 수신 및 AI 서비스 호출           │
└─────────────────────────────────────────────────────────┘

PredictionController.java
    └── triggerPrediction()  [@PostMapping("/{storeId}/trigger")]
        ↓
PredictionService.java
    └── triggerPrediction(storeId)
        └── RestTemplate.postForObject(
                "http://localhost:8000/api/predict/store/{storeId}"
            )
                    ↓  HTTP POST 요청


┌─────────────────────────────────────────────────────────┐
│  STEP 3. AI SERVICE - 예측 실행                          │
└─────────────────────────────────────────────────────────┘

routers/prediction.py
    └── trigger_store_prediction()  [POST /api/predict/store/{store_id}]
        ↓
services/prediction_service.py
    └── predict_and_save_store(db, store_id)
        │
        ├── [1] data_service.get_active_menus(db, store_id)
        │       └── SELECT * FROM MENU WHERE store_id=? AND is_active=1
        │
        ├── [2] data_service.get_store_region(db, store_id)
        │       └── SELECT region FROM STORE WHERE store_id=?
        │
        ├── [3] weather_service.fetch_forecast_weather(region, api_key, days=7)
        │       ├── _fetch_short_term()   ← 기상청 단기예보 API
        │       └── _fetch_mid_term()     ← 기상청 중기예보 API
        │       반환: DataFrame[날짜, 최고기온, 최저기온, 강수량, ...]
        │
        └── [4] 메뉴별 반복 처리:
                predict_and_save_menu(db, store_id, menu_id, ...)
                    │
                    ├── [4-1] data_service.get_sales_data(db, store_id, menu_id)
                    │           └── SELECT sales_date, SUM(quantity)
                    │               FROM SALES_DATA WHERE store_id=?, menu_id=?
                    │           반환: DataFrame[날짜, 판매량]
                    │
                    ├── [4-2] weather_service.fetch_historical_weather(lat, lon)
                    │           └── Open-Meteo Archive API (과거 날씨 데이터)
                    │
                    ├── [4-3] DemandPredictor.fit(sales_df, weather_df)
                    │           └── ml/demand_predictor.py
                    │               ├── feature_engineering.build_features()
                    │               │   ├── add_date_features()
                    │               │   │   (요일, 월, 주차, 주말여부 등)
                    │               │   ├── add_lag_features()
                    │               │   │   (lag_1, lag_7, lag_14)
                    │               │   └── add_rolling_features()
                    │               │       (rolling_mean_7, rolling_mean_14, ...)
                    │               ├── 날씨 피처 병합
                    │               │   (최고기온, 최저기온, 강수량, 비/더위/추위 여부)
                    │               └── RandomForestRegressor 학습 (n_estimators=200)
                    │
                    ├── [4-4] DemandPredictor.predict(days=7, forecast_df)
                    │           └── ml/demand_predictor.py
                    │               └── 7일간 반복:
                    │                   ├── make_future_feature_row()  ← 미래 피처 생성
                    │                   ├── model.predict(X)           ← 예측값 계산
                    │                   └── confidence 계산
                    │                       (R²×85% - 예측일×1.5%, 최소 15%)
                    │
                    └── [4-5] data_service.save_predictions_bulk()
                                ├── DELETE FROM PREDICTION_RESULT
                                │   WHERE target_date >= CURDATE()
                                └── INSERT INTO PREDICTION_RESULT
                                    (store_id, menu_id, target_date,
                                     predicted_qty, confidence, model_version)

[ 4. 판매 데이터 수에 따른 예측 모델 전략 ]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  데이터 수    모델                    신뢰도
  ─────────────────────────────────────────────────────
  7개 미만    예측 불가                0%
  7 ~ 14개   단순 요일 평균            최대 30% (일별 감소)
  15 ~ 29개  RandomForest             최대 40% (일별 감소)
  30개 이상   RandomForest + 날씨 피처  R²×85% (최대 95%)

  신뢰도 감소 공식: 예측일이 멀수록 하루당 -1.5%, 최소 15%

[ 5. 피처 엔지니어링 상세 ]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  입력 데이터:
    - 판매 이력: (날짜, 판매량)
    - 과거 날씨: (날짜, 최고기온, 최저기온, 강수량, ...)
    - 예보 날씨: (날짜, 최고기온, 최저기온, 강수량, ...)

  생성 피처:
    1) 날짜 피처 (7개)
       day_of_week, day_of_month, month, week_of_year
       is_weekend, is_holiday, is_monday/friday/saturday/sunday

    2) 시계열 피처 (6개)
       lag_1, lag_7, lag_14       ← 과거 판매량 참조
       rolling_mean_7, rolling_mean_14, rolling_std_7

    3) 날씨 피처 (6개)
       temp_max, temp_min, precipitation
       is_rainy, is_hot, is_cold
