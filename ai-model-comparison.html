#1 가장 중요한 버그 — Lag Feature 데이터 누수

예측값으로 다시 예측해서 오차가 복리로 쌓이는 구조적 문제
❌ 기존 — 예측값을 lag로 재사용
# 예측 루프마다 history에 예측값 추가
history_working = self._history.copy()

for i in range(1, days + 1):
    feat_row = make_future_feature_row(
        target,
        history_working,  # 예측값 포함!
        weather_row=weather_row
    )
    pred_qty = model.predict(X)

    # 문제: 예측값을 다시 history에 추가
    new_row = pd.DataFrame({
        "ds": [target],
        "y": [float(pred_qty)]  # 오차 누적!
    })
    history_working = pd.concat(
        [history_working, new_row]
    )
✅ 개선 — 실제 이력만 사용
# history_working 제거, 실제 이력만 참조
predictions = []

for i in range(1, days + 1):

        target,
        self._history,  # 실제 데이터만!

    )
    pred_qty = model.predict(X)

    # history 업데이트 없음 → 오차 미전파

        "date": target,
        "predicted_qty": pred_qty,

#4 #5 신뢰도 계산 개선

하드코딩된 50%와 평균 근처 +10% 보너스 제거
❌ 기존 신뢰도 계산
데이터 30개+
R²×85%
데이터 7~9개
0.5 고정
평균 근처 예측
R²×85% + 10%
⚠️ 문제 1: 데이터 7~9개일 때 검증 없이 50% 반환
⚠️ 문제 2: 모델이 항상 평균값만 예측해도 신뢰도 ↑
→ 실제 급증/급감 이벤트를 과소평가
✅ 개선된 신뢰도 계산
데이터 30개+
R²×85%
데이터 7~9개
0.3 (보수적)
평균 근처 예측
R²×85% 동일
✅ 데이터 부족 시 더 낮은 신뢰도로 솔직하게 표현
✅ 예측값 위치와 무관하게 모델 성능(R²)만 반영
→ 신뢰도가 실제 모델 품질을 정직하게 반영
신뢰도 수식 비교
❌ 기존 _calc_confidence()
def _calc_confidence(self, pred_qty, history_df):
    base = self.score * 85.0
    y_vals = history_df["y"].values
    mean_val = np.mean(y_vals)
    std_val  = np.std(y_vals)

    # 예측이 평균 범위 안이면 +10% 보너스
    if std_val > 0 and abs(pred_qty - mean_val) <= 2 * std_val:
        base = min(base + 10.0, 95.0)

    return max(15.0, base)
✅ 개선 _calc_confidence()

    # 예측값 위치 기반 보너스 완전 제거
    return max(15.0, self.score * 85.0)

개선 핵심 한 줄 요약

기존 모델은 예측값을 다시 예측에 사용하고, 날씨 데이터를 0으로 채우고, 신뢰도를 부풀리는 구조적 문제가 있었습니다.
개선된 모델은 실제 이력만 참조하고, 계절 평균으로 날씨를 추정하며, R² 점수로만 신뢰도를 계산해
더 정직하고 안정적인 수요 예측을 제공합니다.
