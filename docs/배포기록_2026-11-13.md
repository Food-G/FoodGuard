## 3. 진행 순서

1. 직접 설치 방식(Nginx + systemd)으로 먼저 배포해 동작 확인
   - 해결한 문제: DB 비밀번호 불일치, 보안 그룹 80번 누락, 보안 그룹 수정 중 SSH 규칙 누락
2. Claude CLI 설치·로그인 → AI 문장 기능(발주 근거 설명, 운영 비서 등) 활성화
3. 내부 키 적용: Docker 에서는 AI 서비스가 `0.0.0.0` 으로 열려 `main.py` 가 키 없이 기동을 거부한다. 키 없음·틀림 401, 맞음 200 확인
4. Docker 설치(공식 저장소) → 이미지 빌드 → 이전 방식 끄고 `docker compose` 로 전환 (중단 약 2분)
5. 컨테이너 안에서 Claude 다시 로그인 (볼륨 `claude-auth` 에 저장, 재시작 후에도 유지 확인)

## 4. 운영 방법

```bash
# 서버 접속 (보안 그룹에 등록된 IP 에서만)
ssh -i <키 파일 경로> ubuntu@13.54.96.115

# 업데이트 (jihwan 에 push 된 뒤)
cd ~/FoodGuard && git pull && sudo docker compose --env-file .env.prod up -d --build

# 상태 / 로그
sudo docker compose --env-file .env.prod ps
sudo docker compose --env-file .env.prod logs -f backend

# 예전 이미지 정리 (디스크 여유가 적다)
sudo docker image prune -f

# 컨테이너 안 Claude 다시 로그인
sudo docker compose --env-file .env.prod exec ai-service claude
```

- 접속은 반드시 `https://`. `http://` 로 연 탭에서 로그인하면 CORS 403 으로 "Failed to fetch" 가 난다
- IP 주소(`http://13.54.96.115`)로는 이제 접속되지 않는다 (인증서가 도메인용)
- 다른 장소에서 SSH 가 막히면 AWS 보안 그룹 SSH 소스를 "내 IP" 로 다시 설정
- 되돌리기: 이전 방식(Nginx, `foodguard-backend`, `foodguard-ai` systemd 서비스) 파일은 남겨 두고 꺼 두었다
- 운영은 `ddl-auto=none`. 로컬 백엔드는 `ddl-auto=update` 로 **공유 DB 구조를 바로 바꾼다** → 컬럼 삭제·이름 변경은 미리 공유

## 6. hyeon 브랜치 통합 가이드

`hyeon`(소문자) 최신 `9788c9d` 는 jihwan 과 갈라져 있다. 프론트 외에 백엔드 기능도 있다.

- 새 API: `/api/employees`, `/api/employee-schedules`, `/api/attendance`, `/api/pos-tables`, `/api/sales/{storeId}/today-summary`
- 새 테이블 `employee`, `employee_schedule`, `attendance`, `pos_table` 은 공유 DB 에 이미 있다 (로컬 `ddl-auto=update`)
- **프론트만 jihwan 에 넣으면** 위 API 가 jihwan 백엔드에 없어 대시보드 오늘 KPI, 직원 관리, 출퇴근, POS 좌석 저장이 오류
- 덮어쓰기는 어느 방향이든 한쪽 기능이 빠진다 → **jihwan 을 hyeon 으로 merge** 한 뒤 jihwan 에 합친다

### 순서

```bash
# 1. hyeon PC: jihwan 을 hyeon 으로 (운영 영향 없음). 브랜치 이름은 소문자로 지정
git checkout hyeon && git pull origin hyeon
git fetch origin jihwan && git merge origin/jihwan     # 충돌 8개

# 2. 충돌 정리 (아래 표)

# 3. 확인 후 push
cd frontend && npm ci --legacy-peer-deps && npx tsc --noEmit && npm run build
cd ../backend && ./gradlew test --tests "com.foodguard.service.*" --tests "com.foodguard.security.*"
git add -A && git commit -m "merge: jihwan(배포 버전)을 hyeon 에 병합" && git push origin hyeon

# 4. 점검 → 5. jihwan 에 합치기 (충돌 없음) → 6. 서버 반영
git checkout jihwan && git pull origin jihwan && git merge origin/hyeon && git push origin jihwan
```

### 충돌 정리

| 파일 | 방법 |
|---|---|
| `backend/.../security/StoreAccess.java` | 양쪽 다: jihwan `MenuDiscount` + hyeon `Employee`, `EmployeeSchedule`, `Attendance` (4줄 모두) |
| `backend/.../SalesDataRepository.java` | jihwan 쿼리 유지 + hyeon `sumDailyByStoreBetween` 추가. 매출은 `COALESCE(s.unitPrice, m.price)` 로 (할인 반영, CLAUDE.md) |
| `frontend/Dockerfile` | jihwan (`127.0.0.1`) |
| `frontend/package.json` | jihwan 버전 기준(취약점 조치) + hyeon 추가 3개(`@mui/icons-material`, `simplebar-react`, `swiper`) |
| `frontend/package-lock.json` | package.json 정리 후 `npm install --legacy-peer-deps` 로 다시 생성 |
| `frontend/src/pages/POS.tsx` | 양쪽 다: jihwan 할인 결제 + hyeon 좌석 배치 |
| `frontend/src/pages/Dashboard.tsx` | hyeon 기준 (2차 개선), jihwan 에만 있는 기능은 옮긴다 |
| `frontend/src/App.tsx` | 양쪽 라우트 모두 |

막히면 `git merge --abort` 로 합치기 전으로 돌아간다. 합친 뒤 POS 할인 결제·좌석 저장, 대시보드 KPI, 직원·출퇴근 화면을 직접 눌러 본다.

참고: `SalesDataService.getTodaySummary` 가 기존 주석 "전 가맹점 최근 7일 매출" 과 그 메서드 사이에 들어가 주석 위치가 어긋나 있다.
